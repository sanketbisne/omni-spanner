SLIDE 2: THE CHALLENGE
================================================================================
Title: The Hybrid/Multi-Cloud Database Dilemma
Bullets:
- Consistency vs. Portability (The standard cloud lock-in)
- High latency when querying across cloud environments
- Maintaining different schemas for cloud (Spanner) vs. on-prem (PostgreSQL/MySQL)
- Complex syncing, replication, and migration logic

Speaker Notes:
- Cloud-native Spanner is amazing, but historically it locked you into Google Cloud hardware due to specialized atomic clocks.
- Now, Spanner Omni bridges this gap, giving you the exact same Spanner engine and API surface anywhere.

================================================================================
SLIDE 3: ENTER CLOUD SPANNER OMNI
================================================================================
Title: What is Spanner Omni?
Bullets:
- Downloadable, self-managed software package
- Runs on Kubernetes (GKE, EKS, vSphere) and bare-metal VMs
- Uses a software-based TrueTime emulator
- Matches the API, dialect, and schema capability of Cloud Spanner
- Supports relational, graph, vector search, and full-text search

Speaker Notes:
- TrueTime emulator provides synchronization using NTP, enabling local transactional guarantees.
- Fits seamlessly into standard GitOps workflows.

SLIDE 4: DEMO ARCHITECTURE
================================================================================
Title: GKE Deployment Topology
Bullets:
- VPC Subnet hosting regional GKE Standard Nodes
- Namespace: spanner-omni (StatefulSets & PersistentVolumeClaims)
- Service Ports: 15000 (Database) and 15026 (Web Admin Console)
- GKE Managed Prometheus scraping metrics on port 15012
- Local Developer Machine linked via background kubectl port-forwards
